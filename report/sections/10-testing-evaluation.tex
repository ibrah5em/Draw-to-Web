\section{Testing Strategy}
% DRAFT (review):
Testing is automated and layered, mirroring the source tree. As of v1.0.0 the
suite comprises \textbf{1042 tests across 110 files}, covering the document model,
generator, runtime snippets, SEO, the export pipeline, templates, the stores, the
user interface, and the v1.0.0 surfaces (\texttt{tests/draw}, \texttt{tests/match},
\texttt{tests/mcp}). Table~\ref{tab:suites} summarises the suites.

\section{Quality Gates}
% DRAFT (review):
Three gates run on every push and in continuous integration: lint (ESLint +
Prettier), strict type-checking (main + renderer), and the full test suite.
Additional automated checks enforce output determinism and the
no-\texttt{position:absolute} invariant, and the \texttt{axe-core} accessibility
gate blocks export on any critical or serious violation.

\section{Performance Evaluation}
% SOURCES: perf-capture-checklist.md; supervisor-report §7; plan §14
% DRAFT (review): report the two categories honestly.
Performance budgets split into two categories. \textbf{Data-layer and export
budgets} are measured headlessly in a dedicated perf lane and pass with large
margins (Table~\ref{tab:perf}). \textbf{Render-layer budgets} (drag FPS, theme
toggle, breakpoint switch, layers scroll, cold-start) require the running
application and a profiler; at the time of writing these are
\emph{not yet captured} and are tracked as a post-release task (issue~\#95). They
must not be reported as measured until captured on demo hardware.
